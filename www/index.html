mch

Mesh Herder

Slow-convergence fleet management for MeshCore repeater nodes.

github.com/rdmarsh/meshherder

You have 30 MeshCore nodes. Logging into each one manually is not a workflow.

mch is a daemon that connects to a locally-attached gateway node over USB serial, walks your mesh, and brings every managed node into a declared desired state — one node at a time, without hammering the mesh.

It is built for unreliable, low-bandwidth networks and intermittently reachable solar-powered field nodes: cache observations, expose what is stale or partial, and converge over repeated opportunities.

Think configuration management for your nodes, running continuously in the background.

Install

git clone https://github.com/rdmarsh/meshherder
cd meshherder
python3 -m venv .venv
source .venv/bin/activate
pip install -e .

Requires Python 3.11+. Linux (Raspberry Pi OS / Ubuntu); macOS for development.

How it works

 mch (CLI)
    |
    | Unix socket
    |
 mchd (daemon)
    |
    | USB serial (/dev/meshcore0)
    |
 Gateway node
    |
   mesh
    |
 Managed repeater nodes
  1. Declare desired state in config.yaml — settings, facts to collect, operations to run.
  2. mchd connects to a locally-attached gateway node and reads the mesh contact list.
  3. Each sync cycle: visit due managed nodes, collect facts, enforce selected settings, and run operations.
  4. Results, drift, and history go into a local SQLite database. mch fleet status shows the fleet.

What it does

  • Desired-state enforcement — declare readable/writable CLI settings; mchd enforces, audits, or skips them with Node > Group > Global precedence.
  • Fact collection — firmware, hardware, role, location, neighbours, and other registered readable values are cached in SQLite. mch daemon validate warns about likely misspelled fact keys.
  • Multi-frequency support — use via_radio: globally, per group, or per node; mchd temporarily switches the gateway when required and restores its home radio afterward.
  • Group name prefix — prepend a name_prefix: (usually an emoji) to each member's desired name, set globally, per group, or per node. No space is added, and mchd refuses to start if a prefix+name would overflow the 31-byte firmware name limit.
  • Staggered scheduler — nodes are spread randomly across the sync window so mchd restarts never cause a surge.
  • Rate limiting — one node at a time, configurable delay between nodes. Never hammers the mesh.
  • Operational evidence — foreground sync reports management radio, cached path mode, reads, failures, and writes; logs record manual sync start, completion, partial results, and aborts.
  • Open-node detection — warns when a node syncs with no ACL protection and surfaces the condition in fleet reporting.
  • mch node exec — run one-off MeshCore CLI commands on any managed node without touching config. Destructive commands require confirmation; irreversible ones are blocked.
  • mch node new — guided wizard to take a freshly-flashed node to fully managed: generates or restores a private key, sets name/password/radio, verifies identity after reboot.
  • Hot reload — mchd watches config.yaml and secrets.yaml and reloads on change. Invalid YAML is rejected; previous config stays active.
  • Read-only integration API — optional loopback HTTP JSON status, plan, issue, and log endpoints for reporting tools and future dashboards.

Minimal config

config.yaml holds daemon settings only. Inventory and desired state (nodes, groups, global defaults, facts) live in the database — the daemon refuses to start if config.yaml still carries nodes:/groups:/global:/facts:. 

gateway:
  device: /dev/meshcore0
  baud: 115200
  radio:
    freq: 915.075
    bw: 125
    sf: 9
    cr: 5

scheduler:
  sync_interval_days: 1
  inter_node_delay_seconds: 120

Run mch gateway contacts to list repeater nodes visible to the gateway that are not yet managed, then bring one under management with mch node adopt and set its desired state with mch config set (or seed many at once with mch config import).

CLI reference

mch status / mch sync              # shortcuts for `mch fleet status` / `mch fleet sync`
mch help selectors / concepts      # learn how to name a node, and mch's vocabulary
mch daemon validate                # validate config/secrets and warn about unknown facts
mch fleet status                   # fleet overview: state, label, group, firmware, neighbours, last seen
mch fleet status <label|prefix>    # filtered table (single match hints `mch node show`)
mch node show <label|prefix>        # full detail for one node
mch fleet plan                     # desired-vs-known diff, no mesh traffic, no writes
mch fleet plan <label|prefix>      # filter to one node
mch fleet sync                     # sweep all nodes in background
mch fleet sync <prefix>            # sync one node now; stream radio/path/command progress
mch fleet issues                   # just the issue sections; exits 2 when any issue is present
mch gateway contacts               # gateway contacts not yet managed in the DB
mch node adopt <pubkey> --radio R  # bring a discovered node under management
mch node group <node> [name]       # set or clear a node's DB group
mch node exec <node> <command>      # run a raw MeshCore CLI command on a managed node
mch node new                       # add a fresh or replacement node (interactive)
mch fleet logs                     # recent per-node activity across all nodes
mch fleet logs <prefix>            # activity for one node
mch fleet suggest                 # suggested txdelay per node based on neighbour count
mch fleet suggest <label|prefix>  # full suggestions + the mch config set commands to apply

Testing and development

The repository includes a manual QA worksheet for service lifecycle, validation, reporting, slow sync/cancellation, and controlled bench-radio testing. It explicitly keeps discretionary tests off the field mesh frequency.

Requirements

  • Python 3.11+
  • Linux — tested on Raspberry Pi OS and Ubuntu. macOS works for development.
  • A MeshCore node attached over USB serial (the gateway node).
  • One or more MeshCore repeater nodes reachable via the gateway.
