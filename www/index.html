mch

Mesh Herder

Fleet management for MeshCore repeater nodes.

github.com/rdmarsh/meshherder

You have 30 MeshCore nodes. Logging into each one manually is not a workflow.

mch is a daemon that connects to a locally-attached gateway node over USB serial, walks your mesh, and brings every managed node into a declared desired state — one node at a time, without hammering the mesh.

Think Ansible for your nodes, running continuously in the background.

Install

git clone https://github.com/rdmarsh/meshherder
cd meshherder
python3 -m venv .venv
source .venv/bin/activate
pip install -e .

Requires Python 3.11+. Linux (Raspberry Pi OS / Ubuntu); macOS for development.

How it works

 mch (CLI)
    |
    | Unix socket
    |
 mchd (daemon)
    |
    | USB serial (/dev/meshcore0)
    |
 Gateway node
    |
   mesh
    |
 Managed repeater nodes
  1. Declare desired state in config.yaml — settings, facts to collect, operations to run.
  2. mchd connects to a locally-attached gateway node and reads the mesh contact list.
  3. Each sync cycle: visit every managed node, collect facts, enforce settings, run operations.
  4. Results, drift, and history go into a local SQLite database. mch status shows the fleet.

What it does

  • Desired-state enforcement — declare any get/set CLI setting; mchd enforces, audits, or ignores per configurable policy per setting, node, or group.
  • Fact collection — firmware version, hardware name, role, battery, uptime, neighbours — collected each sync and stored in SQLite.
  • Multi-frequency support — nodes on different radio settings? Add via: to the node entry; mchd hops the gateway, manages the node, and restores home frequency when done.
  • Staggered scheduler — nodes are spread randomly across the sync window so mchd restarts never cause a surge.
  • DM commands — send sync <pubkey> as a mesh DM from your device to trigger an immediate sync from the field.
  • Rate limiting — one node at a time, configurable delay between nodes. Never hammers the mesh.
  • Open-node detection — warns when a node syncs with no ACL protection. Flagged in the log and in mch issues.
  • mch exec — run one-off MeshCore CLI commands on any managed node without touching config. Destructive commands require confirmation; irreversible ones are blocked.
  • mch commission — guided wizard to take a freshly-flashed node to fully managed: generates or restores a private key, sets name/password/radio, verifies identity after reboot.
  • Hot reload — mchd watches config.yaml and secrets.yaml and reloads on change. Invalid YAML is rejected; previous config stays active.

Minimal config

gateway:
  device: /dev/meshcore0
  baud: 115200
  radio:
    freq: 915.075
    bw: 125
    sf: 9
    cr: 5

scheduler:
  sync_interval_days: 1
  inter_node_delay_seconds: 120

nodes:
  - pubkey_prefix: aabbccdd
    label: MyRepeater
    default_policy: enforce
    settings:
      owner.info: "Managed with Mesh Herder"

Run mch contacts to list repeater nodes visible to the gateway that are not yet in your config, with pubkey prefixes ready to paste in.

CLI reference

mch status                   # fleet overview: state, label, group, firmware, neighbours, last seen
mch status <label|prefix>   # one match: node detail; multiple: filtered table
mch plan                     # desired-vs-known diff, no mesh traffic, no writes
mch plan <label|prefix>     # filter to one node
mch sync                     # sweep all nodes in background
mch sync <prefix>           # sync one node now; CLI waits for the result
mch contacts                 # nodes visible to the gateway but not yet in config
mch exec <node> <command>   # run a raw MeshCore CLI command on a managed node
mch commission               # commission a fresh or replacement node (interactive)
mch logs                     # recent per-node activity across all nodes
mch logs <prefix>           # activity for one node
mch hint                     # suggested txdelay per node based on neighbour count
mch hint <label|prefix>     # full suggestions + paste-ready config block

Requirements

  • Python 3.11+
  • Linux — tested on Raspberry Pi OS and Ubuntu. macOS works for development.
  • A MeshCore node attached over USB serial (the gateway node).
  • One or more MeshCore repeater nodes reachable via the gateway.
